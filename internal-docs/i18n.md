# Internationalization (i18n)

ClavaMetrics ships in **English (base)**, **Spanish**, and **Portuguese**, and is
built so a new language is a drop-in file — no code archaeology required.

- Translations live in **`/locales/<code>.json`** — flat `"dotted.key": "value"` maps.
- The runtime is **`/assets/i18n.js`** — no build step, no dependencies.
- The tooling is **`/scripts/i18n.mjs`** — audit, scan, scaffold, CI check.

---

## 1. Add a new language (the "selling in Asia tomorrow" path)

```bash
# 1. Scaffold a locale file pre-filled with English (nothing is ever blank)
node scripts/i18n.mjs new ja            # -> creates locales/ja.json (372 keys)

# 2. Translate the *values* in locales/ja.json (keys stay in English, untouched)
#    Hand it to a translator or an agency — they never touch code.

# 3. Register the code in assets/i18n.js:
#      var LANGS = ["en","es","pt","ja"];
#      var LABEL = { ..., ja:"日本語" };
#      var NAME  = { ..., ja:"日本語" };

# 4. (optional) Map its countries in COUNTRY_LANG for auto-detection:
#      JP:"ja"

# 5. Verify completeness before shipping:
node scripts/i18n.mjs check             # non-zero exit if any key is missing
```

That's it. The language now appears in the settings selector and in the
marketing language menu automatically.

**CJK / RTL notes.** For Japanese/Chinese/Korean, no plural rules are needed
(handled by `Intl.PluralRules`). For Arabic/Hebrew add `dir="rtl"` handling in
the app shell later — the runtime already sets `<html lang>`; RTL is a CSS pass,
not a translation pass.

## 2. How a string gets translated

Base text stays in the HTML in English; the runtime overwrites it for the
active language. Tag any element:

```html
<button data-i18n="common.save">Save</button>
<input data-i18n-ph="squad.search_player" placeholder="Search player">
<span data-i18n-html="pr.ent.h3">Running <em>10+ categories</em>?</span>
<a data-i18n-attr="title:common.export;aria-label:common.export">Export</a>
```

Interpolation + plurals:

```html
<span data-i18n="squad.player_count" data-i18n-vars='{"count":3}'>3 players</span>
```
```json
{ "squad.player_count": "{count} player|{count} players" }
```

From JS:

```js
CM_I18N.t("squad.player_count", { count: n });   // "3 players"
CM_I18N.applyTo(newlyRenderedNode);              // re-tag dynamic DOM
document.addEventListener("cm:langchanged", () => rerenderCharts());
```

## 3. Key naming convention

`namespace.leaf` — one namespace per page/module, plus shared namespaces:

| Namespace   | Owns                                              |
|-------------|---------------------------------------------------|
| `common.*`  | buttons, generic labels reused everywhere         |
| `shell.*`   | sidebar, top bar, notifications (`assets/sidebar.js`) |
| `settings.*`| settings drawer                                   |
| `mk.*`? no  | marketing keys are **unprefixed** (`nav.*`, `hero.*`, `pr.*`, `sec.*`) — legacy, don't rename |
| `<page>.*`  | page-specific, slug of the file name (`gps_analysis.*`, `squad.*`, `wellness.*`) |

Reuse `common.*` before inventing a page key. `scripts/i18n.mjs scan` proposes
namespaced keys automatically.

## 4. Language detection (priority order)

First hit wins, resolved in `assets/i18n.js`:

1. **Explicit user choice** — `localStorage.cm_lang` (set when the user picks a language).
2. **Cloud user preference** — `CM_I18N.setUserPref(lang)` from `profiles.settings.language`.
3. **Club country** — `CM_I18N.setClubCountry(cc)` → `COUNTRY_LANG` map (`clubs.country`).
4. **IP geolocation** — `CM_I18N.setGeoCountry(cc)` (from an edge function header; optional).
5. **Browser** — `navigator.languages`.
6. **Fallback** — `en`.

Signals 2–4 only apply while the user hasn't made an explicit choice, so a coach
who picks Portuguese keeps Portuguese even on an English browser.

### Wiring the signals (app pages, after auth)

```html
<script src="assets/i18n.js" defer></script>
```
```js
// after the profile + club load:
CM_I18N.setCloudSaver(async (lang) => {
  const { data: { session } } = await sb.auth.getSession();
  const id = session?.user?.id; if (!id) return;
  const { data } = await sb.from("profiles").select("settings").eq("id", id).single();
  await sb.from("profiles").update({ settings: { ...(data?.settings||{}), language: lang } }).eq("id", id);
});
CM_I18N.setUserPref(profile?.settings?.language);   // step 2
CM_I18N.setClubCountry(club?.country);              // step 3
```

### IP geolocation (optional, step 4)

Client JS can't read the caller IP reliably. Add a tiny Supabase Edge Function
that returns the country from the request header (`cf-ipcountry` / `x-vercel-ip-country`)
and feed it in:

```js
fetch("/functions/v1/geo").then(r=>r.json()).then(g => CM_I18N.setGeoCountry(g.country));
```

Persisting to `profiles.settings.language` needs **no migration** — `settings`
is already a `jsonb` column synced by the settings drawer.

## 5. Rollout plan (atomic, page by page)

The runtime + locales are live; pages get tagged incrementally so each step is a
reviewable diff.

```bash
node scripts/i18n.mjs audit                 # see what's tagged
node scripts/i18n.mjs scan "Wellness.html"  # worklist for one page
```

Suggested order (highest traffic / most shared first):

1. **Shell** — `assets/sidebar.js`, `settings-drawer.jsx` (rebuild `.js`), top bar. Unlocks every page at once.
2. **Auth** — `Login.html`, `Register.html`, `Onboarding.html`, `set-password.html`.
3. **Daily-use app** — `Hub.html`, `Squad.html`, `Calendar.html`, `Daily Planning.html`, `Wellness.html`, `RPE.html`.
4. **Performance** — `GPS Analysis.html`, `Load Monitor.html`, `Gym Planner.html`.
5. **Medical** — `Injuries.html`, `Clinical Record(s).html`, `Physio.html`, `Rehab*`.
6. **Admin / billing** — `Admin.html`, `Billing.html`, `Plan Picker.html`.
7. **Marketing** — switch `<script src="i18n.js">` → `assets/i18n.js` (keys already migrated).

For each page: `scan` → add keys to `locales/*.json` → tag elements → for
JS-rendered strings use `CM_I18N.t()` and re-apply on `cm:langchanged`.

## 6. Files

| File | Role |
|------|------|
| `locales/en.json` | base dictionary (source of truth for keys) |
| `locales/es.json`, `locales/pt.json` | translations |
| `assets/i18n.js` | runtime: detection, loading, apply, plurals, interpolation |
| `scripts/i18n.mjs` | `audit` / `scan` / `new` / `check` |
| `scripts/i18n-migrate-marketing.mjs` | one-shot: migrated legacy `i18n.js` DICT → JSON (kept for provenance) |
| `i18n.js` (root, legacy) | old marketing-only runtime; retire after marketing pages switch to `assets/i18n.js` |
